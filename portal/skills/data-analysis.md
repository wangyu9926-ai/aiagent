# 数据分析技能

你被要求完成一次数据分析。先确认数据文件和分析问题，再动手计算；不要凭印象编数字。

## 输入位置

- 用户上传的附件会给出服务器绝对路径。
- 如果用户连接了“本地文件夹”，其服务器镜像路径通常形如 `/uploads/<tenant>/<conversation>/local`。
- 只读取用户明确提供或本地文件夹镜像里的数据文件；不要扫描无关目录，不要读取 `.env`、密钥、配置文件。

## 执行原则

1. 先列出可用文件、字段名、行数、缺失值和明显异常，再开始统计。
2. 如果租户提供 `datalab_query` 工具，优先用它：把 CSV/Excel 文件登记成表，写只读 SELECT/WITH 查询，在服务端 DuckDB 里计算。不要尝试在租户里安装 pandas，也不要让用户装 Python。
3. 如果没有 `datalab_query` 且有代码执行/终端，才用本地代码；两者都没有时，只能用文件工具读取小文件做有限统计，并明确说明“未运行代码、结果可能不完整”。不要假装跑过代码。
4. 指标口径不明确时，先给一个合理假设并标注；确实阻塞时最多问 3 个问题。
5. 所有数字必须能追溯到具体文件、列和过滤条件。

## 输出

- 先给结论摘要（3–7 条），再给明细表/分组统计。
- 需要图表时，调用 `datalab_query` 时加 `chart` 参数：`{type: bar|line|pie|scatter, x: "列名", y: "列名或列名数组", title: "标题"}`。工具结果会返回 `chart_file.url`，把下载链接告诉用户。
- 需要时把清洗后的数据、统计结果写到工作区，文件名清晰，例如 `analysis-result.csv`。
- 如果用户使用本地文件夹桥，告诉用户可以点“同步回本地”取回生成的文件。
- 最后列出数据质量问题、口径假设和下一步建议。

## 数据库分析（仅当已配置数据库工具时）

- 只使用平台提供的只读数据库工具/连接器；不要向用户索要或回显数据库密码。
- 先看表结构和行数，再写只读查询；默认加 `LIMIT`，不要执行写操作、DDL 或跨库扫描。
- 查询结果同样要给出表名、过滤条件和口径。
